# ルール形式

- `INDEX.md`: カテゴリの定義と、件数・最終更新日の索引。
- `<slug>.md`: カテゴリ別ルール本体。

## カテゴリの定義

カテゴリはリポジトリごとに決め、`INDEX.md` の表を唯一の定義とする。スキル側に既定のカテゴリは持たない。slug は表の `ファイル` 列から `.md` を除いたものである。

- 既存の `INDEX.md` があれば、その slug・表示名・対象を正とし、書き換えない。`対象` 列が無い古い `INDEX.md` では、表示名とカテゴリファイル内の既存ルールから範囲を読み取る。
- 初回（`INDEX.md` が無いとき）は、指摘と判定したものから案を作る。
  - 指摘を観点ごとに仮に束ね、複数の指摘が集まる観点をカテゴリにする。1 件だけの観点は `misc` に入れる。
  - 数は 5〜12 程度にする。細かすぎると 1 カテゴリ 1 ルールになり、粗すぎると索引として役に立たない。
  - 技術スタックや構成に固有の観点（特定のフレームワーク、API 契約、翻訳、層の責務など）は、指摘が実際にあるときだけ独立させる。
  - `misc`（その他）は必ず置く。
  - slug は英小文字のケバブケース。ファイル名とルール ID に使うので、確定後は変えない。
  - 各カテゴリに `対象`（どんな指摘を入れるか 1 文）を付け、隣のカテゴリとの境界が分かるようにする。
- 2 回目以降は、既存のどのカテゴリにも収まらない指摘が複数あるときだけ、新カテゴリの案を分類ゲートで示す。承認されたものだけ `INDEX.md` に足す。

## ルール項目

各ルールは次の形式で書く。ID は `R-<slug>-<連番3桁>`、カテゴリ内で採番。

```markdown
## R-type-safety-001: API 定義に無い null 許容は理由を明記
- 適用範囲: src/api
- 最終採用日: 2026-07-09
- 初回作成日: 2026-07-09
- 根拠件数: 3
- 出典: #120, #98, #75
- ルール: 型に null/undefined を追加する際は、API 定義との差異と追加理由を PR 説明かコメントに残す。
- 具体例:
  - #120「API 定義では nullable ではないのに null を許容した理由を教えてください。」
```

- 適用範囲: `全体`、リポジトリ root からのパスや glob（例 `src/api`、`packages/*`）、またはパスで表せない領域名（例 `UI`、`開発環境`）。複数あるときはカンマ区切り。
- 最終採用日: 直近の生成実行で（再）採用された日（`YYYY-MM-DD`）。
- 初回作成日: 最初に作られた日。
- 根拠件数: このルールの根拠となった指摘の数（集合知の支持度）。
- 出典: 根拠となった PR 番号（`#123`）。
- ルール: 汎用化した観点（1〜3 文）。
- 具体例: 実際のコメントの引用（長ければ抜粋）を PR 番号付きで 1 件以上。

## カテゴリファイルの構造

```markdown
---
category: 型安全 / null 安全
slug: type-safety
updated: 2026-07-09
---

# 型安全 / null 安全

（ここにルールを R-... 見出しで並べる）
```

- `INDEX.md` にカテゴリの行を足すときに、ルール 0 件のファイルも作る。
- `category` と `slug` は `INDEX.md` の表示名とファイル名に揃える。
- `updated` は、そのファイルのルールを追加・更新した日にする。`INDEX.md` の最終更新日と同じ値にする。

## INDEX.md の構造

```markdown
# レビュー観点ルール INDEX

`team-review-rules-build` が生成・更新する。各カテゴリの定義と件数、最終更新日を一覧する。

| カテゴリ | ファイル | 対象 | ルール件数 | 最終更新日 |
| --- | --- | --- | --- | --- |
| 型安全 / null 安全 | type-safety.md | 型の厳密さ、null/undefined の扱い、型アサーション | 3 | 2026-07-09 |
| その他 | misc.md | 他のカテゴリに入らない指摘 | 0 | 2026-07-09 |
```

- 承認したカテゴリは、ルールが 0 件でも行を残す。0 件の行の最終更新日は、カテゴリを足した日にする。
- `対象` 列が無い既存の `INDEX.md` は、ルール案ゲートで対象の案が承認されたときに列を足す。承認されなければ列を足さずに残す。

## 冪等マージ規則（再実行時）

- 既存ルールと意味的に一致する指摘が再度出た場合:
  - `最終採用日` を実行日に更新。
  - `出典` に新しい PR 番号を追記（既出 PR は重複させない）。
  - `根拠件数` を新規根拠の分だけ加算。
- 一致するルールがなければ新規ルールとして採番・追加。
- 既存ルールの `適用範囲` などの書き方は、更新するときも書き直さない。
- 意味的一致の最終判断はルール案ゲート（人手）を backstop とする。
- 古いルールの削除（prune）は行わない（更新スキルの責務）。
- 保存後、変更したカテゴリの件数・最終更新日を `INDEX.md` と、そのファイルの `updated` に反映する。
