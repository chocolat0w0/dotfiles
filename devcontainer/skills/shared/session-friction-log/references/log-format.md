# Friction log のフォーマット定義

この文書は、プロジェクト共有ログ `docs/agent-friction-log.md` の書式、カテゴリ、状態、
回数の数え方を定義する。記録データと定義を分けることで、書式の改善と履歴の保持を両立する。

## カテゴリ（固定）

| ID | カテゴリ | 含まれるもの |
| --- | --- | --- |
| A | 仕様・依頼スコープの認識 | 依頼の範囲や前提を取り違えた。聞くべきところを推測で進めた。逆に、判断して進めるべきところで止まった。 |
| B | 権限と境界 | 読み取り専用の対象を編集した。外部システムへ送信しようとした。確認なしに不可逆操作をした。 |
| C | 環境・ツールの前提 | 到達できないホストに接続しようとした。未利用のツールを使おうとした。パスやコマンドが誤っていた。 |
| D | プロジェクト規約 | プロジェクトの正本や規約を見落とした。コミット規約、テスト・lint コマンド、命名規則を取り違えた。 |
| E | 手戻りと非効率 | 同じ調査を繰り返した。不要な確認で往復した。出力が過剰だった。 |
| F | 説明とコミュニケーション | 報告の粒度が合わない。言語の選択。根拠のない断定、または過剰な留保。 |

カテゴリは固定する。同じ原因が分裂して発生回数が伸びなくなるため、新しいカテゴリは
作らない。

## 状態

| 状態 | 意味 |
| --- | --- |
| `未対処` | 記録しただけで、その場の回避もしていない。 |
| `暫定対処` | そのセッションでは回避したが、次回も起こりうる。 |
| `恒久対応済み` | 次のセッションのエージェントが読める場所に、再発を防ぐ判断または機構を適用した。対応先を必ず書く。 |
| `恒久対応見送り` | ユーザー判断で恒久化しないと決めた。理由を必ず書き、再提案しない。 |

同じセッション内で回避した、口頭で伝えた、または個人用の一時的な記録を残しただけでは
`恒久対応済み` にしない。共有の instruction、スキル、dotfiles、または該当エージェントの
設定として判断可能になったときだけ恒久対応とする。

## 発生回数

発生回数は、摩擦を記録した**対象セッション数**で数える。同一セッションで複数回起きても
1 回とする。スキルを実行したセッションではなく、振り返った対象セッションの ID を数える。

### セッション ID

エージェントが自分のセッション ID を取得できるなら、その先頭 8 文字を使う。

取得できないエージェントでは、`<エージェント名>-<日付>-<同日連番>` を ID として使う。
例: `codex-2026-08-20-a`。同じ日に複数回振り返るときだけ連番を `b`, `c` と進める。
形式が違っても回数の数え方は変わらない。ID は対象セッションを一意に指すためだけに使う。

### 二重計上の防止

二重計上は次の二つで防ぐ。

| 仕組み | 役割 | 判定 |
| --- | --- | --- |
| エントリの `記録セッション` | 回数の根拠 | 対象セッション ID があれば加算しない |
| 冒頭の `集計済みセッション` | 振り返り済みの台帳 | 対象セッション ID があれば、再集計の前にユーザーへ確認する |

両者が食い違った場合、回数の根拠である `記録セッション` を正とする。食い違いを見つけたら
ユーザーへ伝える。

## エントリの書式

```markdown
#### F-012: 宣言された境界を確認せずに操作する

- **発生回数**: 2
- **記録セッション**: `a1b2c3d4` (2026-08-12), `e5f6a7b8` (2026-08-20)
- **状態**: 暫定対処
- **内容**: 読み取り専用の対象を変更しようとした。対象の境界を確認する手順がなかった。
- **その場の対処**: 操作を中止し、対象と権限を確認してから再開した。
- **恒久対応候補**: 関連手順の開始時に、対象と許可される操作を確認する項目を追加する。
```

ID は `F-` + 連番で、カテゴリをまたいで通し番号にする。`内容` は事実を再現できる粒度で、
`その場の対処` は実施した一時回避を、`恒久対応候補` は再発防止案を書く。

## 並び順

- カテゴリ内のエントリ: ID 昇順
- 冒頭サマリ表: ID 昇順
- `集計済みセッション`: 日付昇順

サマリ表は派生データなので、更新時に全エントリから作り直す。

## ログ全体の骨組み

`docs/agent-friction-log.md` が無ければ、次の骨組みで新規作成する。見出しの文言と階層は
変えない。エージェントごとに構造が分かれると共有ログとして読めなくなる。

カテゴリ見出しは A〜F の 6 つを常に置き、エントリが無いカテゴリには `(なし)` と書く。
カテゴリごと省略すると、次のエージェントが見出しを作り直して階層がずれる。

````markdown
# Agent friction log

セッション中の摩擦の共有記録。書式の定義はスキル `session-friction-log` の
`references/log-format.md` を正とする。このファイルには記録だけを置く。

## 集計済みセッション

| セッション | 日付 | エージェント | 記録した ID |
| --- | --- | --- | --- |
| `a1b2c3d4` | 2026-08-12 | claude | F-001, F-002 |
| `codex-2026-08-20-a` | 2026-08-20 | codex | (なし) |

## サマリ

| ID | カテゴリ | 見出し | 発生回数 | 状態 |
| --- | --- | --- | --- | --- |
| F-001 | A | 依頼範囲を広げて実装する | 2 | 暫定対処 |
| F-002 | D | テストコマンドを取り違える | 1 | 未対処 |

## 摩擦一覧

### A. 仕様・依頼スコープの認識

#### F-001: 依頼範囲を広げて実装する

- **発生回数**: 2
- **記録セッション**: `a1b2c3d4` (2026-08-12), `e5f6a7b8` (2026-08-20)
- **状態**: 暫定対処
- **内容**: 依頼になかった周辺ファイルまで変更した。
- **その場の対処**: 依頼範囲外の変更を戻した。
- **恒久対応候補**: 着手前に変更対象のファイルを列挙して確認する。

### B. 権限と境界

(なし)

### C. 環境・ツールの前提

(なし)

### D. プロジェクト規約

#### F-002: テストコマンドを取り違える

- **発生回数**: 1
- **記録セッション**: `a1b2c3d4` (2026-08-12)
- **状態**: 未対処
- **内容**: プロジェクトが使わないテストランナーを実行した。
- **その場の対処**: 正しいコマンドをユーザーから教わり実行し直した。
- **恒久対応候補**: プロジェクトの instruction に検証コマンドを明記する。

### E. 手戻りと非効率

(なし)

### F. 説明とコミュニケーション

(なし)
````

骨組みの中の `F-001` と `F-002` は書式を示すための例であり、実データではない。
新規作成時は例を消し、全カテゴリを `(なし)` にした状態から始める。
