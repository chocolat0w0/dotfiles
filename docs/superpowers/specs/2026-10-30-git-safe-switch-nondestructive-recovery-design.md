# git-safe-switch 非破壊復旧設計

## 意図

`git-safe-switch` の復旧処理が、直接 Git を実行して失敗した状態よりも作業ツリーや参照を悪化させないようにする。

## 対象

- 復旧失敗後を含む、パス名だけを根拠とした未追跡ファイルの自動削除を廃止する。
- 復旧を再試行する前に、HEAD・現在ブランチ・元ブランチの参照がスクリプトの操作で到達し得る状態か検証する。
- 復旧で上書きする可能性がある追跡中ファイルの変更や新規未追跡ファイルを検出したら、強制復旧を行わない。
- `-c` で作成したブランチは、通常の直接refで、どのworktreeでも使用されていない場合だけ、作成時のコミットを期待値にした原子的なref削除を行う。
- 想定外の状態を検出した場合は、それ以上変更せず終了コード 4 で復旧を依頼する。

## 対象外

- ignored ファイルの上書き防止
- シグナルに対する完全な復旧
- Claude Code フックの迂回防止や既存設定への自動導入
- Git 操作の完全な原子性

## 検討した方法

1. 現在の自動削除と強制復旧を維持する: 残骸は減るが、並行して作られたファイルや更新された参照を破壊し得るため不採用。
2. 復旧処理を完全に廃止する: 追加破壊は避けやすいが、今回追加したガードの価値がほぼなくなるため不採用。
3. 復旧前に状態を検証し、自動削除を行わない: 復旧可能な通常ケースは維持し、想定外の状態では停止できるため採用。

## 確認方法

一時リポジトリとテスト用 Git ラッパーを使い、残存未追跡ファイルを削除しないこと、追跡中ファイルの変更を強制復旧で上書きしないこと、参照が外部更新された場合に強制的に戻さないこと、作成ブランチの削除直前に更新が競合しても削除しないこと、symbolic refや別worktreeで使用中のブランチを削除しないことを自動テストする。
